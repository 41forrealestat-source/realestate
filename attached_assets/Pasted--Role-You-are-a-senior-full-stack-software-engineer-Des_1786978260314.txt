## Role

You are a senior full-stack software engineer. Design and implement a production-ready real estate management platform using **Next.js** and **MongoDB**.

## Project Goal

Build a simple real estate marketplace/management application for listing and managing:

1. **Real Estate Builds / Properties**
2. **Apartments**
3. **Lands**

The application must allow users to browse listings and clearly determine whether a property is **for sale** or **for rent**.

### Important business rule

* **Builds/Properties:** can be **for sale or for rent**
* **Apartments:** can be **for sale or for rent**
* **Lands:** are **for sale only** and must **never have a rent option**

## Authentication

Do **not** implement authentication or authorization.

The application should work without login, registration, sessions, or user accounts.

For now, owner information is simply stored as information attached to each listing.

## Technology Stack

Use:

* **Next.js** with the App Router
* **TypeScript**
* **MongoDB**
* **Mongoose** or the official MongoDB driver
* Modern responsive UI
* Server-side/API routes where appropriate
* Environment variables for database configuration

Keep the architecture clean and easy to extend later.

## Main Features

### 1. Property Categories

Create three listing categories:

* Builds / Properties
* Apartments
* Lands

Each listing should have a clear category.

### 2. Listing Type

Each listing should have:

* `sale`
* `rent`

However, enforce the following rule:

```text
land → sale only
build → sale or rent
apartment → sale or rent
```

The UI must not display a "Rent" option when creating or editing a land listing.

The backend must also validate this rule so it cannot be bypassed through an API request.

### 3. Listing Information

Every listing should contain:

* Title
* Category
* Listing type: Sale/Rent
* Description
* Price
* Owner information
* Location
* Images
* Created date
* Updated date

Owner information should include at minimum:

* Owner name
* Phone number
* Email
* Optional additional contact information

For rent listings, make it possible to represent the rental pricing period, such as:

* Monthly
* Yearly

For example:

```text
Price: 5,000 SAR
Listing type: Rent
Period: Monthly
```

For a land:

```text
Price: 850,000 SAR
Listing type: Sale
```

### 4. Dashboard

Create an admin-style dashboard even though there is no authentication.

The dashboard should allow the user to:

* View all listings
* Add a listing
* Edit a listing
* Delete a listing
* View listing details
* Filter by category
* Filter by sale/rent
* Search by title/location
* Sort listings by price/date

Show summary statistics:

* Total listings
* Total builds/properties
* Total apartments
* Total lands
* Properties for sale
* Properties for rent

### 5. Public Listings

Create a clean property browsing interface.

Users should be able to:

* Browse all listings
* Filter by category
* Filter by sale/rent
* Search listings
* View property cards
* Open a property detail page

Each property card should clearly show:

* Property image
* Title
* Category
* Sale/Rent badge
* Price
* Location
* Short description
* Owner/contact information or a button to view contact information

### 6. Property Details

Create a dedicated details page for each listing.

Display:

* Large image/gallery
* Title
* Category
* Sale/Rent status
* Price
* Rental period if applicable
* Description
* Location
* Owner information
* Contact details

For lands, never show rental-related information.

## MongoDB Data Model

Design a clean MongoDB schema.

A listing should conceptually look like:

```ts
{
  title: string;
  category: "build" | "apartment" | "land";
  listingType: "sale" | "rent";
  description: string;
  price: number;

  rentalPeriod?: "monthly" | "yearly";

  owner: {
    name: string;
    phone: string;
    email?: string;
  };

  location: {
    address?: string;
    city: string;
    district?: string;
  };

  images: string[];

  createdAt: Date;
  updatedAt: Date;
}
```

Add validation so:

```text
category === "land"
```

requires:

```text
listingType === "sale"
```

and does not allow `rentalPeriod`.

## API

Create clean API endpoints for:

* Get all listings

* Create a listing
* Update a listing
* Delete a listing

Validate all incoming data on the server.

Do not rely only on frontend validation.

Return appropriate HTTP status codes and useful error messages.
